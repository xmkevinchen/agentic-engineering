## 一、一个观察

今天，在一次意图被反复讲清的会话里，一个跨家族评审席读了正确的文件、给出了全场最深的一条发现、产出形状与真品无法区分——**而它从未调用过 backend**。

原因是一句手写的先导指令覆盖了 agent 定义的首要动作。没有任何机制发现这件事；唯一让它暴露的，是提示里一句要求它核对自己工具调用记录的话。

同一天，同样的失效换了一种机制又发生一次：这次不是指令冲突，是任务描述的密度把首要动作挤掉了。第一次用 sonnet，第二次用 haiku。

**失效不在模型的能力上。** 写那句先导指令的人知道自己要什么，agent 也忠实执行了它读到的东西。失效发生在**意图与到达 agent 的那段文字之间**——而那段距离不会因为模型变强而消失。

## 二、一条命题

> **软件工程的正确性，不能由执行它的那一方自己宣布。**

这不是关于 agent 的新话。测试、代码评审、CI、双人复核——整个行业早就建立在这条上。**AE 的工作，是在执行者变成 agent 之后，把这条重新装上。**

它也解释了为什么这一层不会随模型变强而过时：模型越强、自主度越高，能够自证的空间就越大，而**没有任何模型可以做自己的证人**。

## 三、四句话与一条棘轮

### 边界由 Agents 起草、由人确认

什么算做完，写在契约里。而写这件事本身要分成两步，因为两边各有对方没有的东西：

- **Agents 起草**——它们读过代码，知道什么可验、验证手段长什么样、哪条标准写下来是空的。让人从零写验收契约，写出来的一定是薄的，而**薄契约是下游一切问题的根**。
- **人确认**——意图、取舍、责任在人这边。而且更根本的一条：**起草者不能确认自己起草的东西**，那正是第二节那条命题。

三条随之而来：

1. **确认必须是可拒绝、可修改的。** 如果人唯一能做的是点"是"，那边界实际上是 agent 定的，确认只是橡皮图章。
2. **放到人面前的东西要在正确的高度**——业务上什么算对，不是 recipe 和实现细节。看不懂的东西无法被拒绝。
3. **起草会带着起草者的盲区。** 本仓记录过一条追溯不到任何讨论决策的 AC，它随后失败，几乎让一个满足用户全部明示条件的 feature 被判为失败。那是一条无人确认的、agent 起草的边界——**而确认这一步是唯一能抓住它的地方**。

契约管的是**业务上什么算对**，不是怎么实现。AE 本身不含项目事实，只出槽位；内容由起草的 agent 填，由人确认。

### 证据管完成

完成由**可复核的证据**决定，不由任何一方的声明决定。

`exit 0` 只证明"被批准的命令在那个快照上退出了 0"。LLM 的 `pass` 只证明"它给出了一个判断"。两者单独都不等于正确。

证据是历史，不是最后一份漂亮报告：失败不被覆盖，状态可从磁盘重放。

### Agents 管执行

怎么做、开几个人、用什么模式、几轮评审——**全是可替换的手段，不代表质量**。

多 agent、跨家族、辩论、doodlestein，都不进入"什么算做完"的定义。它们只在能改变最终做出来的东西时才值得付钱。

### 知识管复利

贵到不该被第二次发现的东西要留下，**且它自带失效条件**。

留下的判据不是"这条有用"，是"重新发现它要花多少钱"。没有读取命中的知识库不是螺旋，是堆积。

### 人只在边界上出现

人不逐阶段批准。人**确认边界的每一次设定与变更**，此外不出现。

零打断和十次无效打断，在"人不在环里"这个失效模式上是等价的。前者是放弃，后者是流程同步伪装成判断。

---

### 贯穿五者的一条：棘轮

> **任何一层都可以收紧，不可以放松。**

- 契约：可加 AC，不可删 AC
- 验证手段：可加维度、可把判断升级为可执行检查，不可降级、不可放宽区间
- spawn 指令：可收窄一个 agent 的职责，不可解除它定义层的义务
- 计划：可以整份重写；真值不可以

这是整套东西**唯一的对称性破缺**，也是它能自洽的原因：

**如果任何一层可以双向调整，执行者总能把标准调到自己刚好够得着的地方。** 而它不需要恶意——今天那两次降级都是善意的、为了把活干好而做的调整。

**一处必须分清的界**：棘轮作用在**标准的强度**上，不作用在**范围**上。把已同意范围内的标准提得更严，可以自由提议；**扩大范围不行，哪怕它看起来只是"顺手把这个也做了"**。前者是收紧，后者是另一件事，任何方向的范围变动都要重新确认。

## 四、每一条各自删掉了什么

一条哲学如果不能说明它使什么得以删除，它就是又一份要长期维护的散文。逐条举证：

| 条款 | 它删掉的 |
|---|---|
| 边界由 Agents 起草、由人确认 | "plan 同时是验收标准"这个双重身份；冻结的自相矛盾（清除一条错误 AC 要重开冻结文件，而冻结正是为防这个）；以及"人从零写 AC"这个不现实的前提 |
| 证据管完成 | "一个 LLM 说 pass 就算过"；六种 `verify_by` 的六套控制流（运行语义只有三类：进程执行 / 判官阅读 / 人回答） |
| Agents 管执行 | 222 行的编队配比规则；"跨家族默认全开"的成本；"reviewer 数量代表质量"这个隐含前提 |
| 知识管复利 | "图健康"这个假指标——它测的是写入侧，而这一层该被判的是读取侧 |
| 人只在边界上出现 | 逐阶段确认；以及主干上那句指向不存在事件的注释 |
| **棘轮** | 三处各自为政的特例规则（Cast 不可放松 / AC 不可自弃 / 验证手段不可降级）合成一条 |

## 五、什么不属于哲学

以下都是**可替换的**，改它们不改变 AE 是什么：

- **阶段名**（analyze / discuss / plan / work / review）——用户心智模型与调用入口，不是本体
- **Agent Teams、跨家族、doodlestein、TDD、reviewer 编制**——执行策略
- **目录结构、字段名、文件格式**
- **模式的名字**——Evaluator-Optimizer、Reflexion、guardrail 这些是查已知失效模式用的坐标，不是 AE 的词汇表

判断一件东西属不属于哲学，问一句：**它消失了，"什么算做完"会不会变？** 不会，就不属于。

## 六、诚实的边界

AE 不是安全沙箱。一个拥有当前用户全部文件权限、且刻意同时伪造契约、证据、Git 历史与检查程序的进程，无法被工作区内的摘要防住。用户始终可以绕开 AE 手工搬文件。

AE 保证的是一件更基础的事：

> **在受支持的路径上，未经验证的东西不能被包装成"已完成"。**

具体地说，以下都会 fail closed 而不是悄悄通过：契约漂移、过期证据、没有实际运行的检查、执行者的自评、不可验证的降级、以及提前归档。

同样要诚实的是**批准的真实性**：当前宿主没有给插件一个可独立验证的"这条回答来自人类"的凭证。人的批准由前台交互与可关联记录支撑，那是**流程保证，不是密码学身份**。说不清楚这一点，整套东西就会在自己最不该含糊的地方含糊。

---

## 七、一句话

> **边界由 Agents 起草、由人确认；完成由证据决定；做法由 Agents 定；知识让下一次更便宜。每一层只能收紧。**
